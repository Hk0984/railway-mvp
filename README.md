# Railway Lab

**OuDia2ndの時刻表を読み込み、列車の乗換案内と、区間ごとの混雑を調べるWebアプリです。（以下Codexによる仕様説明）**  
列車の時刻だけでなく、駅の利用者数や編成の輸送定員を入力すると、「どの列車・どの駅間が混みそうか」をダイヤ図で確かめられます。

[アプリを開く](https://hk0984.github.io/railway-mvp/)

> **バージョンについて**：このREADMEは**開発中のMVP 0.7**を対象としています。公開ページに反映されている版は異なる場合があります。また、混雑人数・混雑率は**入力データと仮定に基づく推計**であり、実測値や将来の混雑を保証するものではありません。

## まずは試してみる（ファイル不要）

アプリには**架空の5駅・72列車**のサンプルが入っています。初めて使うときは、次の順で操作してください。

1. 画面上部の**「データ設定」**を開き、**「サンプルを開く」**を選びます。
2. **「乗換案内」**で出発駅・到着駅・時刻を指定し、**「経路を検索」**を押します。列車や乗換の候補を確認できます。
3. **「混雑ダイヤ図」**へ移動し、**「混雑を計算」**を押します。
4. ダイヤ図上の**列車の線（スジ）**や駅間を選び、推定乗客数・混雑率を確認します。

最初はサンプルのまま操作し、慣れてから自分の時刻表を読み込むのがおすすめです。

## 自分の時刻表で使う

1. **時刻表を開く**：**「データ設定」→「ファイルを開く」**から、OuDia2ndの `.oud2` ファイルを選びます。読み込み後に不足している設定が案内されます。必要に応じて**「対象ダイヤ」**も切り替えます。
2. **営業する列車を指定**：**「営業区分と輸送定員」**で、列車種別が営業・非営業・要確認のどれか確認します。要確認の列車は計算対象から除外されるため、必要な列車を明示的に営業へ設定します。
3. **混雑率用の定員を入力**：**「編成の設定方法」**で列車種別または運用番号を選び、**「輸送定員（人／編成）」**と**「編成両数」**を入力します。運用番号では `32D` と `07D` は `**D`、`32SH` は `**SH`、`39C●` は `**C●`、`A01` は `A**` と表示されます。FileType 1.17では、駅・番線・時刻から接続を一意に確認できるとき、前列車の運用番号を引き継ぎます。運用番号が未確定の場合やグループの値が空欄の場合は種別の値を使い、列車別の設定があれば優先します。定員が分からない区間では混雑率を算出できません。
4. **需要を入力**：**「駅利用者数」**に1日あたりの乗車・降車人数を設定し、**「時間帯の振り分け」**を選びます。時間帯の割合を手動で設定するときは合計を100%にしてください。目的地への到着時刻を指定する場合は、初期設定で到着需要をなだらかに補間します。
5. **保存して計算**：画面下部の**「設定を保存」**を押し、**「混雑ダイヤ図」→「混雑を計算」**へ進みます。保存できなかった場合は、保存ボタンの横に理由が表示されます。

路線外から乗り入れる利用者も考慮する場合は、**「路線外方面」**で接続駅や流入・流出人数を設定できます。ただし、路線外の区間そのものを検索・描画する機能ではありません。

## 3つの画面でできること

| 画面 | できること |
| --- | --- |
| **乗換案内** | 出発・到着駅と時刻から、路線内の利用可能な列車・乗換経路を検索します。候補の要約を一覧で比較し、選んだ経路の停車駅や混雑状況を確認できます。結果の発着時刻は分まで表示します。 |
| **混雑ダイヤ図** | 横軸を時刻、縦軸を駅として列車の動きを表示します。計算後は駅間ごとの混雑率を色で重ね、表示位置や選んだ列車・区間を保ったまま詳細を確認できます。 |
| **データ設定** | 時刻表の読み込み、駅別利用者数、時間帯、列車の営業区分・定員、路線外方面、保存・読み込みを行います。 |

## 結果の読み方

**混雑率**は「その駅間の推定車内人数 ÷ 1編成の輸送定員 × 100」で計算します。たとえば、輸送定員100人に対して推定120人なら**120%**です。色分けはアプリ独自の段階で、ダイヤ図では色やしきい値を変更できます。公的な混雑区分と同じとは限りません。

**線（スジ）の色が付いていない区間**は、停車中・配分対象外・輸送定員未登録などにより、混雑率が表示できない場合があります。「区間情報」の**未算出**は「空いている」という意味ではありません。

**車内模式図**は、1両あたりの平均的な人数を簡略化して示したイメージです。ドア・座席の配置や乗客の位置は仮定を含み、実際の車内を再現したものではありません。

**駅別の降車人数**は行先を決める重みとして使います。推計結果の降車人数が入力値に必ず一致するわけではありません。計算できなかった人数は**「需要と計算条件」**で確認できます。

## FYI

**Q.「混雑を計算」がうまくいかない場合：**  
営業列車が設定されているか、駅の乗車・降車人数や時間帯に需要があるかを確認してください。混雑率を表示するには輸送定員も必要です。

**Q. 24時以降の時刻を入力する場合：**  
運行日の翌0時30分は**`24:30`**と入力します。翌日の時刻表を自動で繰り返すわけではありません。

**Q. 分岐路線でも使えますか？**  
対応している分岐構造では扱えます。混雑ダイヤ図の**「表示経路」**で系統を切り替えられます。ただし、環状線や複雑な運用は完全対応ではありません。

**Q. 需要区分の変更方法：**  
**「需要の日区分」**で月〜木・金曜日・土休日を選べます。金曜日・土休日の専用設定がなければ月〜木の設定を使用します。**「対象ダイヤ」**とは別に選択できます。

**Q. 保存した設定はどこにありますか？**  
編集した内容はブラウザ内に保存されますが、ブラウザデータを削除すると失われる場合があります。**「データ設定」→「設定のJSONを保存」**で、バックアップファイルも保存してください。JSON出力前には**「設定を保存」**が必要です。

**Q. ダイヤ改正後も駅利用者数を使えますか？**

**「ファイルを開く」**から新しい `.oud2` を開きます。駅名と駅順（分岐を含む）が一致すれば、駅利用者数や曜日別の需要設定を引き継ぎます。同じ駅順の設定JSONを開く場合は、現在開いているダイヤに設定を適用します。列車との対応を確認できない個別設定がある場合は、読み込み後の案内を確認してください。

## 対応範囲・注意点

- OuDia2ndの**FileType 1.07 / 1.17**を部分的に読み込めますが、OuDia2ndの全機能と互換ではありません。ファイルの読み込み上限は**20MB**です。
- 駅の着時刻・発時刻が1件も入っていない列車は除外し、時刻がある列車で解析します。ファイル内のすべての列車に駅時刻がない場合は、その旨を表示します。
- **途中停車駅に発時刻だけがある場合**、着時刻は空欄のまま扱います。その駅からの乗車と同じ列車での乗り通しは可能です。その列車からの降車や別列車への乗換を、乗換案内や混雑計算に含めるには着時刻が必要です。ダイヤ図では発時刻で前後のスジをつなぎます。停車を表す横線は、着時刻と発時刻がそろい、時刻差がある場合に描きます。分岐駅で同じ駅の着発が列車の訪問順で連続する別の行に分かれている場合は、1回の停車として扱います。
- **乗換案内は対象路線内**の検索です。路線外の線路・停留所や運賃、他社線を自動で補完しません。
- 混雑推計は入力した駅利用者数・時間帯・行先の重み・輸送定員などに左右されます。実際の乗降や混雑の再現精度は未検証です。
- 計算やファイルの読み込みは基本的に**ブラウザ内**で行います。開いた時刻表を解析用サーバーへ自動送信する仕組みはありません。

## 開発者向け

Node.js **20.19以降の20系、22.12以降の22系、または24以上**を用意し、リポジトリを取得した後に実行します。

    npm ci
    npm run dev

ブラウザで `http://127.0.0.1:5173` を開きます。検証には次を使います。

    npm test
    npm run build
