# MVP 0.6：競合・時刻仮定・旅客追跡の監査

MVP 0.5を `9b52aad` に保存してから開発した。0.4は `69edfe8`。従来の読込、警告、営業区分、需要生成、配分、校正、比較、保存を維持する。

## 利用方法と互換性

「複数路線・統合配分」で架空サンプルを追加し、「0.6：競合・時刻精度・診断」を開く。乗車競合を「同時刻一括」、診断を「全件」にして保存・実行すると、旅客追跡と任意時刻の人数監査を利用できる。単一データセットも選べる。新しいサンプルは同時刻一括が初期値。

`competition` 未設定／`legacy` の旧保存データは登録順の0.5互換動作を保つ。従来の単一路線「旅客配分・混雑分析」画面も互換動作。新方式は統合画面で明示選択する。診断を旧結果へ後付けして実行済みのように表示しない。

既存schemaVersion 1へ任意フィールドを追加し、駅ID・列車ID・分類・定員を再生成しない。統合設定はワークスペースJSONへ保存する。計算結果は別の分析JSON。読込失敗時に既存データを置換しない。計算方式・条件・入力・日区分対応・データセット／ダイヤ・計算版0.6・利用率／生成前提・実効徒歩・定員設定根拠を結果に記録する。需要シナリオを実行した結果は、その名称・倍率・適用条件も保持する。

## 同時刻処理

時刻は従来どおり運行日00:00からの秒。24時以降も連続して扱う。時刻表の秒を補完しない。

同一時刻の既知の降車、需要発生、アクセス／徒歩完了を発車段階より先に反映する。降車で空席を解放し、最低乗換・徒歩・追加時間・締切を満たす乗車候補を確定してから、**全発車イベントを一括**して処理する。

1. 乗車可能時刻 `ready` の早い集団を優先するFIFO。乗換集団は物理的な駅到着だけでなく、最低時間・追加時間が満了した時刻を使う。
2. 同じ `ready` の集団から、利用可能な同時刻便への提案量を計算する。最速方式は早着・乗換回数・費用が同等の候補へ、ロジットは目的別係数の確率へ配分する。
3. 各列車の**共通残定員**を使い、同着提案の人数比で受入人数を決める。整数は最大剰余法。同じ列車に同時刻の異なる停車イベントがある場合も、定員を二重に使わない。
4. 全列車の受入量を同じ提案スナップショットから決めて反映する。残った集団は、残定員のある同時刻候補へ再提案する。利用不能な経路には提案しない。
5. 同時刻候補を使い切った残りを積み残しとし、将来計画を破棄・再探索する。乗換前後は同じOD集団。後続便・明示した別乗り場への徒歩にも対応する。

同着・同余の整数タイブレークは、OD内容の正規化キー、到着時刻、利用履歴の順。OD入力順を優先しない。経路の本質的条件が同じ場合に残るタイブレークは列車IDを用いる。区別不能な重複OD行の個々の端数や、全く同等の列車への端数の所属まで一意・匿名に決めることはできない。IDを変えた同等便の人数・完了・最大混雑等の集計不変を試験している。実数の演算順による微小差は収支検査の許容差内で扱う。

**ゼロ所要区間の規約**：同時刻の発車段階で乗車した列車が同じ時刻に到着する場合、その降車は発車段階の後。すでに出発した同時刻便へ遡及乗車しない。閉じた接続を診断へ記録し、後続便を再探索する。発車段階より前に到着済みの便からは、最低乗換0秒・締切0秒を明示すれば同時刻乗換が可能。これは時刻表で分解できない順序に対する解析規約で、実際の停車順を推定したものではない。

将来便の満員を先読みした全ネットワーク最適化、経路類似度補正、連続個人の厳密FIFO、全経路の網羅は未対応。候補上限も結果に影響する。これらを最適解と表示しない。

## 枠内時刻と乗車境界

`ArrivalModel.timing` は省略時 `midpoint`。

| 方式 | 到着時刻の仮定 | 数量の扱い |
| --- | --- | --- |
| A `midpoint` | 従来どおり分割セルの中点 | 既存の一様／前半／後半／任意重み。整数は最大剰余 |
| B `start` | 分割セルの開始 | 同じ需要量をセル開始へ集中させる条件付き評価 |
| C `uniform` | 枠内に一様、既定1秒の数値積分 | 各セルの質量を積分し、中点を使う |
| D `weighted` | 指定分布、既定1秒の数値積分 | 前半／後半／任意重み等を積分し、中点を使う |

元の刻みより細かい積分刻みは1〜60秒で設定できる。発車・待ち上限・総所要・締切・重みの境界でも分割する。C/Dも**数値積分による集団近似**であり、連続個人の実測時刻ではない。1OD枠10万分割超はエラー。

枠開始・積分は「時刻分布モデル」で使用する。従来代表時刻と同時に選ぶ矛盾した設定は保存・実行時に拒否する。検索の所要上限は駅到着から目的地まで。表示の旅行時間には明示アクセスも含むため、その分だけ検索上限を超えることがある。

C/Dの整数化は、累積確率に対する丸め `round(N×CDF)` の差分を使う。低密度の1秒枠へ最大剰余を適用すると同余が先頭へ集中するため、その偏りを避ける。決定的で乱数不要、行の人数は保存する。A/Bの旧整数結果は変更しない。時間窓で切り出した人数が非整数になる整数設定は従来どおり拒否する。

入力時間は出発駅で探索し始める時刻。アクセスは明示した `accessSeconds` だけ加算する。乗車条件は、初回は `駅到着 ≤ 発車−締切秒`、乗換は `前列車の着＋物理徒歩＋追加時間＋最低乗換 ≤ 発車−締切秒`。締切0なら等号を許可。乗車イベント・定員確定は発車段階に記録し、実際のドア締切時刻を観測したとは扱わない。

例：サンプル60人・07:00–07:15・07:10発に対し、Aは40人、Bは44人、C/Dの一様は40人が輸送完了する。Bでは07:10のセルも開始時刻へ集中させるため差が出る。時刻情報だけで実際にどの仮定が正しいかは確定できない。「時刻精度4方式」の完了／未輸送・平均待ち・平均旅行・最大人数／混雑率・積み残し・追加待ち・最終到着を比較する。変動幅は保証された上下限ではなく、設定した条件の幅。

前半集中の人工例（60人、0〜60秒、30秒発）では実数需要45人が乗車できる。1秒積分の平均待ちは解析値50/3秒に0.01秒以内で一致する。容量競合・整数丸めを含む全結果に同じ誤差上限を保証するものではない。

## 診断・追跡・人数収支

新方式の定員制約結果には `audit` を付ける。集団に元OD行・到着セル、分割元 `parentId` と起点 `rootId` を保持する。需要、初期経路、乗車候補、経路選択、乗車、降車、徒歩開始／終了、集団分割、定員不足、積み残し、再探索、完了、終了時点の未輸送を記録する。発生していない不明接続や収支エラーを作らない。

人数台帳は需要発生前・待機・車内・徒歩・完了・初期経路なしを相互排他的に管理する。各状態変更で全体の和・非負性を確認し、時刻ごとの監査点も記録する。積み残し後に後続経路がない集団は待機状態で理由を保持し、輸送完了としない。最終的に、到着セル別人数、旅程・徒歩の成立性、列車乗降・車内残数・定員以下を再検証する。

- **概要**：イベント件数と監査点。監査点は1000件を超えると間引き、指定時刻以前の最新点を表示する。個別追跡は未記録と表示する。
- **全件**：状態遷移を保持し、任意秒の人数を再構成する。OD行・駅・列車でログを絞り、200件ずつ表示する。50万件超は概要への切替を促すエラーとし、不完全な全件記録を完成扱いしない。

診断CSVは全ログ、診断JSONは設定・入力・監査・最終集団履歴を含む。概要のCSVはヘッダーのみ。未輸送理由を0人や完了へ置き換えない。既存の営業未確認・不明定員・パーサー警告は引き続き表示する。徒歩未設定が経路不在の原因と確定できない場合は断定しない。

## 性能と応答性

同じ列車の停車情報を旅程ごとに全複製せず、**結果内で所有するクローン**を共有する。検索索引の原本とは共有しない。経路の配列・乗降位置・CSV集計は保持する。同時刻候補・積み残し後の検索窓は、個々の集団の期限より広い共通窓で検索して共有し、集団ごとの期限で再度フィルターする。条件を省いて期限違反を許可するキャッシュではない。

検索、需要展開（順位付け・初期配分を含む）、イベント生成、イベント実行、乗車候補検索、再探索、集計、検証の時間を結果へ記録する。候補検索・再探索はイベント実行の内数。初期配分と展開は同一ループのため、その2つを独立した測定値とはしていない。

Workerの計算時間と、送信直前からメイン受信までの「転送・スケジューリング」、DOM描画時間を分けて記録する。純粋なコピー時間やペイント完了時間ではない。進捗はテキストのみ更新し、ログはページ分割する。中止時はWorkerと結果を破棄する。表全体の仮想スクロール、結果の分割転送、TypedArrayへの全面置換は未対応。

測定結果は [VALIDATION.md](VALIDATION.md)。直通疎ODでは改善したが、同時刻候補・監査を追加した小中規模容量配分等は遅くなる。110駅の容量・徒歩ありは依然約23秒。Node・Chromeプロセス全体・メイン描画ヒープを区別し、Worker単独ピークヒープを測定したとはしない。

## シナリオ・比較の信頼性

従来9条件の都市・重力モデル感度を維持し、統合画面に11条件の仮定幅（需要±20%、最低乗換±20%、前半／後半、定員±20%、待ち係数+20%、需要増＋定員減の複合）を追加した。`AssignmentScenario` は複数条件を同時適用できる。元都市・登録OD・定員を変更しない。車両定員は整数へ丸め、需要倍率の整数モードではシナリオ合計を四捨五入後、OD内容順の最大剰余配分で保存する。実測を倍率変更した入力は推計として扱う。統計的な信頼区間ではない。

固定需要比較はOD行順・JSONプロパティ順だけの違いを正規化して照合する。OD・目的・時間帯、到着分布、選択係数・候補数・整数化、競合、乗換・締切、集計窓・上限、定員取扱・設定根拠、実効徒歩、利用率・生成前提を照合し、差異を表示する。比較期間・ダイヤの違いを隠さない。

輸送完了率、共通輸送人数、時間比較から外れた人数を併記する。未輸送者を0分として平均改善を主張しない。OD／時台の完了・未輸送・待ちの差、駅／時台の積み残し人回、列車最大断面の差を実数値から抽出する。追加・除去された列車も表示し、別ダイヤのIDを同一車両とは推定しない。因果の説明・未輸送ペナルティ・金銭換算は自動生成しない。

実測人数の提供はない。独立検証用の用途分離と人工観測による機能試験を維持し、今回も実路線の精度を実証したとはしない。期間・日区分の異なる観測を安易に混ぜない。
