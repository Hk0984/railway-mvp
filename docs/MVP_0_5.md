# MVP 0.5：統合旅客配分と駅到着時刻の精密化

0.4をローカルコミット `69edfe8` に保存してから拡張した。0.3は `d50a551`。既存の単一路線分析・読込警告・保存形式を維持し、新たに「複数路線・統合配分」を追加した。計算はローカルのWeb Workerで行い、中止するとWorkerを終了する。再開・途中結果の保存には対応しない。

## 操作例

1. 「複数路線・統合配分」の架空サンプルを追加する。鉄道とバス、徒歩連絡、需要60人が設定される。実在の接続ではない。
2. 対象データセット・ダイヤ・共通日区分・対応根拠を確認し、設定を保存する。
3. 徒歩時間180秒、追加乗換60秒、最低乗換60秒の片方向連絡を確認する。
4. 代表時刻／1分単位、分布、配分方式、定員制約を選んで実行する。比較ボタンでは同じ入力を代表時刻・一様分布と新方式で比較する。
5. OD流動、利用経路、時間別人数、旅客状態、列車の乗降・断面人数、最大区間へのOD寄与を確認し、CSV・JSONを出力する。

一様分布・整数配分では、07:00–07:15の60人中40人が07:10の鉄道に間に合う。徒歩後にバス25人便へ乗り継ぎ、15人は後続便へ再配分される。輸送完了40人、経路なし20人。前半集中では分単位の最大剰余配分により54人が初便に間に合う。丸め方法を変えた連続分布の理論値と一致するとは限らない。

## モデルと識別

- 駅は `[datasetId, stationId]`、列車は `[datasetId, timetableId, trainId]`、停車イベントはさらに訪問位置と着／発を含むタプルで識別する。同名・同番号だけで統合しない。
- `AssignmentDemand.destinationDatasetId` を追加。省略時は出発側データセットなので旧ODと互換。同じ駅IDでも異なるデータセットなら対角ODにはしない。
- `ServiceMapping` に共通日区分、設定根拠、各データセットのダイヤID・日区分を保存する。選択と一致しない対応、重複データセット、異なる日区分は拒否する。名前から平日や運行日を判定しない。
- 各データセットの時刻は従来どおり運行日の00:00からの秒数。同一運行日を利用者が対応付ける。日付・タイムゾーン・運行日起点の差を自動補正しない。24時以降も連続秒で扱い、翌日便を複製しない。
- `TransferLink` に `enabled`、`additionalTransferSeconds`、`restrictions` を追加した。制約タグは許可リストとの完全一致で判定する。車椅子等の設備情報を推定する仕組みではない。
- 未登録、無効、未許可の連絡は利用しない。片方向は逆に使わない。複数連絡は明示リンクによる最短徒歩接続として探索する。
- 接続条件は「降車時刻＋物理徒歩時間＋追加乗換時間＋最低乗換時間≦次の発車」。最低時間を各徒歩辺で重複加算しない。営業区分・乗降可否・原訪問順・分岐行の対応を保持する。

## 駅到着分布

時間帯ODの時刻は、出発駅で乗車機会を探し始める時刻。`accessSeconds` を明示した行のみ、その時間だけアクセス中として駅到着を遅らせる。未設定なら0秒。

`ArrivalModel` は方式、分布、刻み秒、任意重みを持つ。旧保存データの未設定は従来の代表時刻・一様分布として扱う。

| 分布 | 時間枠内の位置 x（0〜1）に対する密度 |
| --- | --- |
| 一様 | 1 |
| 前半集中 | 2(1−x) |
| 後半集中 | 2x |
| 任意重み | 入力した非負重みを、枠内の等幅区間へ割り当てて正規化 |

基本刻み60秒。型・計算は1秒以上へ細分化可能だが、1OD枠あたり10万分割を超える設定はエラー。発車、初期待ち上限、総所要上限、任意重みの境界でも分割し、その区間の確率質量を積分する。セル中点をその集団の到着時刻として選択・容量処理に使う。**個人ごとの連続時刻を完全再現するものではなく、セル内には中点近似が残る。** 分布と刻みは結果JSONに保存する。

実数は残差補正、整数は最大剰余法でOD行の総量を保つ。時間窓で切り出された人数が非整数になる整数設定は拒否する。乱数は使わず再現可能な期待人数を配分する。最短方式は駅到着から目的地到着まで、ロジットは目的別の乗車・待ち・徒歩・乗換係数を使う。候補上限と非劣経路による選択集合であり、全経路の列挙ではない。

## 統合容量制約とイベント順

全データセットで1つの安定順序付き二分ヒープを使い、車内残数を列車の完全修飾キーごとに共有する。需要行・目的ごとに別定員を設けない。各集団は元OD行と到着セルを保持し、乗換時に新しい需要を発生させない。

同一時刻は次の優先順、同じ優先度は登録順に処理する。

1. 到着・降車：空席を解放する。
2. 需要発生・アクセス／徒歩完了：駅で乗車可能になる。追加・最低乗換時間は発車成立条件として検査する。
3. 発車時の乗車・定員確認：待ち行列順に乗車し、残りを積み残しとして保持する。

同時刻のゼロ所要区間で新たに発生する降車イベントは、次の未処理発車より先に処理する。ただし、すでに出発した同時刻便への遡及接続は成立させず、検出した場合はエラーにする。同時発車便を容量均衡させる最適化・満員先読みは未対応。

積み残し時は古い将来計画を破棄し、現在位置または明示徒歩で到達する駅から後続経路を探索する。初期待ち・総所要・残り乗換回数の上限を維持し、追加待ちを実時刻から集計する。車両定員は輸送定員のみを使用し、座席数とは区別する。不明定員は推測せず、エラーまたは利用者が選んだ明示除外とする。

終了時点は輸送完了・待機・乗換待機・車内・徒歩中・経路なし・期限切れ等の状態を保持する。車内や徒歩を強制的に完了させない。終了後の未観測断面は空欄で、0人と表示しない。

`AssignmentResult.capacity` が制約後の実現した推計輸送、従来の `allocations` / `totals` は初期予定配分。CSV・流動集計は容量結果がある場合そちらを使用する。旅程CSVは1乗車区間1行なので、人数の全行和は延べ乗車人数。需要総人数とは区別する。

検証はOD・到着セル・終端状態の人数保存、徒歩と乗車の接続、発着時刻、駅・ダイヤ・列車の完全修飾ID、乗降可否、列車別乗降収支・車内人数・既知定員以下を確認する。

## 疎ODと性能

需要0の行は探索を省略する。OD行の疎リストを使い、密な全駅対行列を配分用に作らない。直通検索は出発駅・時間条件の初回ラベルを目的地間で共有する。索引のWeakMapに保持し、16条件／2万ラベルを上限とする。既存のプロフィールキャッシュも保持量を制限する。

候補全件に途中停車配列を複製せず、選ばれた旅程に実訪問列から復元する。公開検索・保存結果は途中駅を保持する。時系列イベントは毎回ソートせずヒープで取り出す。画面のOD詳細は先頭100件を表示し、全件CSVを用意する。

結果の有効性は需要・分布・全配分設定・ダイヤ・営業分類・定員・駅・徒歩条件のスナップショットで判定する。未保存編集または条件変更後の古い結果は使わない。索引はWorkerの実行単位で作成する。

性能値とメモリ計測の範囲は [VALIDATION.md](VALIDATION.md)。0.4保存実装と代表時刻・直通の全配分明細、旅程、区間人数、候補数を比較した。1分方式や統合容量方式を旧方式と同値と主張するものではない。

## 流動・検証・感度分析

OD別に時間帯人数、経路別人数、輸送完了／未輸送、平均待ち・旅行時間、乗換回数分布、積み残し追加待ちを表示する。平均時間は輸送完了者に条件付け、未完了人数を併記する。列車別に乗降・断面人数・最大区間・定員・混雑率と、その**最大区間に実際に乗っている**主なOD・目的の寄与を表示する。寄与率は集計結果であり、因果関係を証明しない。路線外の未解析区間は生成しない。

「需要校正・シナリオ・比較」に検証用途だけの散布図、MAE・RMSE・平均誤差・相対誤差、過大／過小推計を追加した。相対誤差の分母0は未算出。観測の追加列 `datasetId,dayGroup,startSeconds,endSeconds` で対応条件を明示できる。従来11列CSVも読める。列車IDが衝突する観測はデータセット未指定なら比較から除外する。期間内で条件の異なる観測も拒否・除外理由を報告する。

IPF・格子探索の最適化に検証用途の行を入れない。**日間ODの校正は時間帯別校正に未対応**で、部分時間帯の観測と日間推計を直接比較しない。列車・断面の実測比較は配分結果のダイヤ・日区分・集計期間との一致が必要。利用者提供の実測値はないため、今回確認した誤差表示は人工観測による機能試験であり、実路線での妥当性実証ではない。

感度分析は基準、β×1.2、雇用吸引×1.2、通勤発生×1.2、通学発生×1.2、鉄道利用率×1.2（上限1）、待ち選択係数×1.2、既知定員×0.8／1.2の9条件。需要量・輸送完了・未輸送・混雑率・積み残し・平均旅行時間を比較する。需要再生成を伴うため、固定ODダイヤ便益とは別実験。元都市属性・登録OD・不明定員は変更しない。各条件の失敗は欠測と理由を表示し、0と扱わない。

## 固定需要のダイヤ便益

同一入力ODでの配分結果から人数加重旅行時間・待ち時間、総人分、乗換人数、OD／時間帯別の増減を計算する。旅行時間は駅到着から最終着まで（明示アクセスは含む）、乗車・徒歩・待ちを含む。未完了者の所要時間を0と扱わない。

両側で輸送完了した共通人数のみ時間差比較し、それ以外を比較対象外として併記する。入力OD行・到着時刻順の累積人数を対応付け、改善・悪化・不変人数を求める。ロジットの個々人の同一性は観測できないので、これは集団の対応規則を置いた評価であり実測個人便益ではない。金銭換算はしない。

従来比較の有効本数・間隔は選択した1OD、追加した旅客加重指標は配分に使った全入力ODが対象。比較画面の列車混雑表と合わせて読む。A/Bで計算期間・到着分布をそろえて利用する。入力需要が違う結果の便益計算は拒否する。

## 保存・出力と制限

ワークスペースschemaVersion 1に任意の `integration` を追加し、各プロジェクトの駅ID・列車ID・分類・定員は再生成しない。未設定時は旧動作。JSON読み込み時は検証が完了してから反映する。ワークスペースJSONは統合設定・全データセット・連絡・需要を含む。単体プロジェクトJSONには統合設定を含めない。計算結果は別の分析JSONを保存する。

統合需要CSVは次の厳密なヘッダーを使用する。

```text
datasetId,origin,destinationDatasetId,destination,purpose,kind,startSeconds,endSeconds,passengers,source,accessSeconds
```

選択対象外のデータセットを参照するODはエラー。対象変更時に需要を勝手に捨てない。旧画面の時間帯ODは追加操作で取り込めるが、その後は独立した入力として保持する。

未対応：カレンダー生成、実ファイル2路線間の未確認接続、外部区間の経路、レコード間の直通確定・増解結、遅延・時変定員、連続個人到着の厳密FIFO、同時便の容量均衡、時間帯別実測ODの校正・交差検証、候補類似度補正、全経路列挙、Worker単独の連続ピークヒープ取得。大量結果の構造化転送と描画には応答遅延・メモリ増加が残る。
