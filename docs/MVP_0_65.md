# 0.65 UI改善：有効本数・営業設定・運用記号定員・経路表示

## 定義

同じ発駅・着駅について、許容する乗換回数・最低乗換時間を満たす旅程を比較する。旅程Aより**発駅を遅く発車し、目的駅へ同時刻以前に着く**旅程Bがあれば、Aは有効本数から除外する。乗換回数がBの方が多くても、上限内であれば除外の根拠に使う。列車種別名だけでは速達性を判定しない。

- 07:00発・08:00着の直通と、07:10発・2回乗換・08:00着なら、後者の1機会のみ。
- 乗換を1回までに制限すると後者は使えず、前者を計上する。
- 後者の到着が08:01なら、早着と遅発のトレードオフなので両方を計上する。
- 集計終了後の後発も比較する。先発が窓内・代替後発が窓外なら、窓内の有効本数は0になり得る。
- 同一発車時刻は最速到着の1出発機会。列車レコード数・経路の組合せ数を加算しない。

この判定は既存の `effectiveJourneyDepartures` にあり、経路検索画面でも使用していた。今回、直通比較だけだった「ダイヤ分析」画面へ公開した。乗換旅客配分・列車選択の候補を消す変更ではない。

## 画面

「ダイヤ分析」の上段に「ODの有効本数（乗換対応）」を追加。上の発着駅・方向・種別・時間帯と選択ダイヤを使用する。乗換0〜4回・最低乗換時間を設定し、分析ボタンを押す。初期上限は2回。重い計算はWorkerで実行し、中止できる。条件変更時は前の結果を消去する。

有効な発着時刻・乗換回数・利用旅程、期待待ち・利用可能割合・間隔統計を表示する。展開欄では、窓内の先発直通列車について、置換の根拠となる後発の時刻と乗継を表示する。すべての除外された乗換旅程を列挙する機能ではない。

新分析は旅客営業列車のみ。従来の全列車の発車分析と直通比較は残し、「直通内で有効」「直通の期待待ち」等と表示して、乗換込みの指標と区別する。単一の選択データセット内が対象。データセットをまたぐ分析は既存の経路検索を利用する。運賃や外部区間を推定しない。

## 検証

第1項の追加6件：2回乗換による同着置換、乗換上限、集計窓外の後発、後着なら両方有効、乗換時間不足／非営業の除外、同時発車重複の排除。既存151件を含む157件すべて成功。Chromeで例示のダイヤを読み込み、1回／2回の切替・置換の根拠表示・方向フィルター・結果無効化・取消・390pxを確認済み。TypeScript・ビルド・既存の画面スモークも成功した。

## 第2項：営業区分・定員のチェックボックス

営業／非営業／要確認をチェックボックスで選ぶ。1行で1つだけ有効。選択を外すと種別は要確認へ、個別列車は種別設定の継承へ戻る。未確認を非営業や営業と推定しない。個別列車には継承のチェックも表示する。

列車種別の予備定員・列車個別定員・運用記号定員は「定員を設定／指定」をチェックして人数を入力する。チェックしただけでは人数を補完しない。解除はその設定を削除し、継承へ戻る。「輸送定員として使用」もチェックボックスとし、オフなら座席数として保存して輸送制約には使わない。既存の座席／輸送定員の区別を維持する。

## 第3項：運用番号の英字記号別定員

「営業区分・定員」の上段に、明示運用番号に含まれる英字記号別の一覧を追加。例：01C・03CはC、15DはD。英字は大文字に正規化し、連続した英字は1つの記号とする。種別名や列車番号の英字を代用しない。設定はデータセット内の全ダイヤに共通。元の列車種別定員は予備設定として残す。

優先順位は、個別メタデータ→従来の個別定員→運用記号→種別メタデータ→従来の種別定員→ダイヤ標準。設定値は配分・混雑率・輸送制約に共通適用し、配分CSVの定員出典に `operation` を記録する。座席のみの指定を輸送定員へ置換しない。

FileType 1.17の作業3/4の入出区連携コードを運用番号と取り違えず、前作業の運用番号を抽出する。1.07の旧書式、前列車接続に明示された仮運用番号、番号変更の明示値も扱う。空の接続情報から別列車の番号を推定しない。複数番号・途中変更で異なる番号がある場合は自動適用せず、列車欄に理由を表示する。同じ記号の複数編成でも定員を合算しない。

列車欄の運用番号上書きはJSONの任意フィールド `Train.operationNumbers` に保存し、空欄に戻すと原文に基づく値へ戻る。設定は `capacitySettings.operationGroups`。原文・駅ID・列車IDは変更しない。既存JSONに新設定がなければ従来どおり。途中の増解結や区間別車両定員は未対応。

解釈の一次資料：[OuDiaSecond公式・1.07の駅作業／番線](https://oudiasecond.seesaa.net/article/467843165.html)、[1.10以降の連携コードと運用番号](https://oudiasecond.seesaa.net/article/481081211.html)、[1.13の番号順反転](https://oudiasecond.seesaa.net/article/485711374.html)。実ファイルはローカルで参照し、外部送信していない。

## 第4項：経路カード

経路の途中一覧・駅数から通過駅を省き、停車駅だけを表示する。検索エンジンと旅程データの通過情報は保持し、通過駅で乗降可能にする変更ではない。

表示を「種別／列車全体の行先」に変更。検索で降りる途中駅を行先にしない。外部終着名が明示されていればそれを使い、外部区間を新しく検索することはない。その他は元の列車レコードの運行区間終端を使う。列車番号は別行で保持する。ダイヤ・データセットは検索条件で引き続き確認できる。

各乗車区間の発駅・着駅に番線名を併記する。OuDiaの `$0` 等は0始まりの添え字であり、元の駅行のTrackNameへ照合する。単純に「1番線」へ変換しない。分岐統合で到着行と出発行が異なる場合は、それぞれ原時刻・原駅行で解決する。未記載・曖昧・定義外・空の番線は「番線情報なし」とし、補完しない。

## 第2〜4項の検証

追加13件で運用書式、連携コード除外、優先順位、複数番号、途中変更、座席との区別、JSON往復、実ファイルの明示記号、実配分定員出典、通過情報の表示だけの省略、列車の行先、外部行先、番線添え字・分岐別着発を検証。全170件成功。Chromeでチェック・解除、運用記号別定員、個別上書きと継承、保存復元、行先・番線・通過省略、PC／390pxを確認済み。既存のブラウザ配分試験はドロップダウン操作をチェックボックス操作へ変更し、同じ計算条件で成功した。
