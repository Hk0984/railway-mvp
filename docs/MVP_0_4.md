# MVP 0.4：計算仕様と制限

## 互換性・保存

0.3のコード・資料をローカルコミット `d50a551` に保存しました。0.2は `064eb6b` です。実ファイル・生成物・秘密情報を含めていません。原本・既存コピーは変更しません。

Project.schemaVersion=1を維持し、任意の `capacitySettings`、`analytics.version=1` と配分設定を追加しました。従来データは定員無制約のまま読み込めます。既存JSON・圧縮ブラウザ保存を維持。入力は検証後に置換し、不正な追加設定も読み込みエラーにします。配分・比較結果はメモリ内で、再起動後に再計算します。観測・校正記録・需要シナリオ・定員根拠はJSONとブラウザに保存します。

## 大量OD・キャッシュ

乗客を1人ずつ展開せず、同じ到着枠と経路を持つ集計人数で処理します。索引オブジェクトごと・発着ID・時間範囲・乗換条件・候補条件ごとにプロフィールを保持し、別ダイヤや別分類の索引と共有しません。128条件・計50,000個の旅程内停車位置まで保持し、大きすぎる単一結果はキャッシュしません。Projectを直接編集した場合は既存の `invalidateRoutingCache` を呼び、索引を作り直してください。

同じOD・到着代表時刻・目的の候補順位とロジット費用を再利用し、検証も同じ旅程と時刻の再照合を省きます。返却する旅程・停車位置はコピーし、呼出元による変更が検索キャッシュを壊さないようにしました。Workerには不要な観測・全シナリオ・保存需要のコピーを送らず、配分対象需要を別に送ります。Worker進捗・中止を維持します。

`assignment-performance.test.ts` は0.3保存実装と小20レコード/12列車、中200/48、大2,000/120を比較。各規模で共通する2OD・時間枠・目的を繰り返し、直通のみの最短＋ロジットを実行します。乱数は使用せず入力は決定的です。人数・到着枠・配分明細・未配分・全列車集計が一致することを確認します。実ファイルの別試験は乗換・分岐を含みます。このベンチマークだけで全ODが異なる巨大ネットワークの速度を保証しません。

計測JSONは `artifacts/assignment-performance.json`。heapUsed・RSS・プロセス最大RSSと前後差も記録します。GCは制御せず、同一プロセスで前後の結果を保持するためメモリ差を削減率とは扱いません。ブラウザWorker単位の厳密なピークメモリ分離計測は未対応です。重い試験同士の競合とRPCタイムアウトを避けるためVitestはファイルを順次実行します。

## 定員の意味・優先順位

CapacitySpecは人数、`kind=transport/seats`、根拠、任意の編成・車両情報です。輸送制約・混雑率にはtransportだけを使用し、座席定員を輸送定員へ読み替えません。値は利用者が設定でき、立席を含む輸送定員も表せます。

優先順位は個別メタデータ→旧Train.capacity→種別メタデータ→旧typeCapacities→ダイヤ標準です。旧定員は従来の設定輸送定員として保持します。営業区分画面のメタデータエディターで対象ID・根拠を指定して追加／削除できます。個別設定がある列車には標準定員を上書き適用しません。

制約時の定員不明便は既定で計算を止めます。利用者が明示した場合だけ除外し、便数を警告に残します。対象索引全体を検査するため、需要時間窓外の不明便も確認対象です。無制約では不明便も利用可能ですが混雑率は未算出です。

## 時系列配分と積み残し

1. 0.3互換の時刻成立候補から最短／目的別ロジットで予定旅程を作成します。到着枠内の一様到着を候補の成立境界で分割し、集計枠の中点を代表到着時刻にします。
2. 全営業便の明示した駅着発を時刻順で処理します。同時刻は降車を先に処理し、乗車待機列は乗車可能時刻・元の駅到着時刻・安定IDの順です。待機列は希望便単位で、将来の便の席を予約しません。
3. 降車後の車内人数を差し引いた残席だけを乗車させます。部分乗車は人数だけを分割し、旅程を複製して人数を増やす処理はしません。下流区間だけの乗客を上流区間へ計上しません。
4. 乗れなかった部分の旧予定を取り消し、現在駅・目的地・残る乗換回数・元の総所要期限から再探索します。同時刻の他便への再試行は行わず、失敗した発車より厳密に後の便だけを探します。最初の乗車までは元の初期待ち上限も維持。再探索でも最短／ロジットを使用します。
5. 乗換駅で失敗した場合も、その駅から新しい経路を探索します。元の旅程の後続区間を自動で乗車済みにしません。再探索不能なら待機理由を保存し、需要を消しません。

各時点の状態はcompleted（目的地到着）、inTransit（車内）、waiting（乗車待ち・積み残し）、noPath（初期経路なし）で排他的です。対象需要と状態合計、到着枠ごとの保存、乗降イベント、定員上限、列車の乗降差と終了時点車内人数を検証します。終端の車内人数を0に補正しません。計算終了以後の未観測区間は混雑率・CSVを空欄／期間外とします。

積み残し経験人数は最終人数の実人数、延べ積み残しは同じ旅客の再発を含む人回です。後続便乗車も再配分された乗車イベント数です。追加待ちは失敗した発車から後続便に乗るまでの人秒で、画面は人分。最後まで待機する旅客の未完了待ちは、この確定した追加待ちに含めません。駅の最大待機は代表到着時刻による在庫推計で、個人の連続到着を厳密再現した値ではありません。

制約結果は `AssignmentResult.capacity` に保存します。元の `totals/allocations/journeys` は初期予定配分です。実輸送の状態・乗降・区間人数には `capacity.totals/events/loads/packets` を使用してください。UIとCSVはこの区別を適用します。乗換イベント数は旅客実人数の保存式へ足しません。

## 実測・校正

観測CSVの列順は次の通りです。画面からテンプレートを保存できます。

```csv
kind,stationId,origin,destination,timetableId,trainId,segmentIndex,period,value,source,role
```

- boarding/alighting：stationId。od：origin/destination。load：timetableId/trainId/segmentIndex（統合後の実列車訪問順における0始まり区間位置）。不要列は空欄です。
- periodは利用者が指定する同一観測期間ラベル、valueは人数、sourceは必須の出典、roleはfitまたはvalidationです。日数や時間窓の自動換算はしません。
- IDで厳密照合し、駅名による対応付けをしません。同一キー・期間・用途の重複や不正区間・負数・出典空欄は拒否します。

第一段階はIPFで、明示承認した駅別人数を往路ODの発生・集中制約として調整します。通常の駅乗車人員は帰路・乗換を含み得るため、意味の確認なしには使いません。構造的ゼロを埋めず、矛盾・到達不能・未収束を報告します。最大500反復。全駅の発生集中総量が違う場合は停止します。

第二段階はfit用ODのみを使い、β（現在値・0・0.01・0.025・0.05・0.1・0.2）と雇用吸引係数倍率（0.5・1・2）の有界格子探索でRMSE最小を選び、その後IPFを適用します。連続最適化や最適解の保証はありません。吸引力が雇用だけなら共通倍率は相殺されるため、その係数を識別できるとは主張しません。

validationは一切係数選択に使いません。用途別の件数・MAE・RMSE、観測／推計／誤差人数／相対誤差を表示します。観測0の相対誤差は未算出。元の係数・選択係数・種となる往路・固定費用・期間・対象駅・収束・除外理由を記録します。校正後ODは推計値であり個別ODの実測とは表示しません。未収束結果は適用できません。

load観測はOD校正から分離し、直近の旅客配分の対応断面と比較できます。観測期間と配分時間窓の一致を利用者が確認した場合だけ計算します。対応しない便・終了後区間は件数に含めません。

## シナリオ・ダイヤ比較

自動生成、実績OD入力、ハイブリッドを保存・切替可能。人口・雇用・学生・利用率・時間集中を変更して生成し、現在需要をそのまま保存することもできます。実績ODはfit用途・指定期間のODを使用し、目的情報がないため通勤往路として明示採用します。ハイブリッドでは観測OD組の自動生成分を置き換え、他のODを保持。帰路・時間配分は既存の仮定を使用します。出典を保持します。

シナリオには比較用の一律輸送定員を任意保存できます。比較時だけ個別・種別定員より優先し、元の共通定員は変更しません。通常の「需要切替」は固定需要の切替で、配分画面の定員は別途設定します。

同一データセット内の2ダイヤを、同一の固定時間帯需要・配分条件で比較します。運行本数・直通有効本数・乗換込み有効出発機会・平均最大間隔・期待待ち・最速到着旅程所要・最大混雑率・積み残し・確定追加待ち・輸送人数を前後差で表示しCSV出力。無制約時の積み残しは0と捏造せず未算出です。別モードで同じダイヤの2需要シナリオと定員条件も比較できます。需要再推計型の改正比較ではありません。

## 残る制限

- 容量配分は単一データセット・同一駅内乗換のみ。徒歩リンクを含む場合は明示エラーです。通常の無制約経路検索の徒歩機能は維持します。
- ゼロ所要乗車自体は扱いますが、その直後に同時刻で乗り換える容量配分は停止します。遅延・ホーム人数制限・車両運用・増解結は扱いません。
- 経路候補は非劣候補・上位K件で、全経路列挙ではありません。満員を先読みした均衡配分、別経路間の相関補正、同時刻便間の容量再配分は未実装です。
- 集計枠の代表時刻によるFIFO近似です。細かな到着順、非常に大きなOD数への疎行列最適化、Workerピークメモリ分離測定は今後の課題です。
- 原ファイルにない定員・運賃・外部OD経路・未確定レコード間直通は生成しません。既存警告を保持します。観測不足では算出可能な指標だけを表示します。
