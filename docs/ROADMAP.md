# 次の実装優先順位（MVP 0.3）

0.3で営業分類・個別上書き、索引キャッシュ・親経路共有、最短／ロジット配分、乗降・断面人数・混雑率、Worker・CSV・保存則検証を追加しました。以下の優先順位を現在の計画とし、後段の0.2計画は履歴です。

1. **P0：配分の校正と性能**。実測OD・乗降・断面人数による係数校正、候補上限の感度分析、疎OD・プロフィール共有・路線走査、ピークメモリの隔離計測。通常検索のWorker化。
2. **P0：容量制約**。積み残し、次便繰越、深夜の未処理需要保持。混雑依存の再選択と保存則検証。
3. **P1：データ精度**。OuDiaSecond本体との照合、既存の路線外時刻不一致2件の確認、根拠のあるレコード間直通・種別変更・増解結のモデル化。
4. **P1：ネットワーク・分類編集**。複数データセット配分UI、駅ID対応表、徒歩・アクセス、一括分類と差分履歴。
5. **P2：比較**。固定ODシナリオ、改正前後の混雑比較、経路類似度補正、交通ゾーン・交通手段分担、不確実性評価。

## 0.2時点の計画（履歴）

0.2では経路検索、手動徒歩連絡、データセットライブラリ、4目的・時間帯別ODと帰路、固定需要とサービスの比較を実装済みです。以下は残る開発項目です。

## P0：読み込みの実用性と検証範囲を拡大

1. 今回取り込んだ1.17実ファイルをOuDiaSecond本体表示と照合し、路線外作業と駅時刻にある不一致2件を確認する。未知版・環状線・増解結の検証資料も追加する。
2. 経路画面の対象種別選択を基礎に、営業・回送・試運転等を利用者が明示分類し、既存分析／需要費用にも共通の分類を適用する。名称だけでは推定しない。
3. 前次列車接続と途中種別変更を結ぶ仕組みを導入。現状保持のみの駅作業0/3/5/6を運用・旅客継続の両面で検証する。FileType別アダプターと互換表も拡充する。
4. 読み込みプレビュー・差分確認、駅時刻の情報源選択、別ファイル間の駅ID対応表を追加。0時表記は今回の明示的な解析運行日起点規約を基礎に検証範囲を広げる。

## P1：需要シナリオとネットワーク

1. 現在のデータセットごと1シナリオから複数シナリオの版管理へ拡張。固定日間OD・時間分布・実測値の比較と校正、発駅別の未配分理由を詳しく表示する。
2. 現在のStationRef / TransferLinkと分岐対応を基礎に、完全なLine/Linkグラフ、初終端の徒歩・徒歩だけの移動、交通ゾーンを追加する。
3. 現在のラウンド型多ラベル経路検索を、路線走査・逆方向プロフィール・Workerへ高速化する。待ち・乗換を含む時間帯別の経路費用を需要モデルの明示的な固定スナップショットとして利用する。
4. Workerへの計算移行、列車・駅時刻索引、疎OD行列、画面仮想化。大規模データで性能を測定する。

## P2：列車配分と混雑

1. 決定論的な最速到着配分から始め、運賃・乗換・着席を考慮した列車選択モデルへ拡張。
2. 時間帯別ODを列車・区間へ配分し、乗降と断面輸送量の保存則をテストする。
3. 定員を組み合わせた混雑率、容量制約と積み残し・次便への繰越を実装。

## P3：比較・補正・交通手段分担

1. 駅IDを揃えた改正前後のサービス・需要・混雑比較。
2. 実測ODを用いたパラメータ校正と誤差・不確実性評価。
3. ゾーン別アクセス時間、他交通機関との分担。

未実装機能のダミー画面や、実際には算出できない混雑率などは現在表示していません。
