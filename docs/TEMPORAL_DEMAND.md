# 目的別・時間帯別ODモデル

## 既存モデルとの共存

従来のProject.parameters / Project.demandsと重力モデル画面は維持します。新モデルはProject.temporalConfig（編集中の条件）とProject.temporal（日間・時間帯需要、固定費用、生成時の係数スナップショット）で独立して保存します。

目的はcommute=通勤、school=通学、shopping=買物、private=その他私事。旧JSON・CSVのprivateも読み込めます。係数や初期時間分布は架空の例であり実測校正はありません。

## 日間の往路

目的別に `O_i = 人口 × 鉄道利用率 × 日間発生係数`。吸引力は雇用・学生数・商業指標をそれぞれの係数で重み付けします。既存の発生制約型重力モデルで目的地へ配分し、対角を除外します。欠損費用・吸引力なしは推測せず、未配分量として表示します。

費用は手動時間行列、または利用者が生成操作時に選んだ現在ダイヤの最短直通時間の**固定スナップショット**です。後者は待ち・乗換を含む一般化費用ではなく、回送等を含む登録全種別から算出します。共通の営業分類を適用する拡張は今後の課題です。

日間需要を生成した後にダイヤや検索オプションを変えても、保存した人数・費用・時間分布は変えません。日間再生成ボタンを押した場合だけ日間モデルの係数と費用を再適用します。日間人数の手動上書き・実測値設定は当該ODの発生制約から外れるため、元の発生モデルの総量とは区別します。

## 時間分布と総量保存

1時間／15分の時間枠を持ち、解析日開始から24時間分の目的別相対重みを正規化して日間往路を分割します。実数モードでは最後の非ゼロ枠へ浮動小数点残差を調整します。整数モードでは各日間OD人数を整数へ丸め、最大剰余法で枠へ配分します。日間人数を時間分割する段階で総量を増減させません。

時間枠変更では1時間の重みを4分割、15分の重みを4枠ずつ集約します。手動のOD別時間配分も同様に変換し、帰路は新しい時間枠で再計算します。帰路も独立に総量保存するため、往路＋帰路の全体も保存します。浮動小数点の整合性検査はOD・目的・往復区分・出典ごとに1e-6人以内です。

時間枠の人数を利用者が編集した場合、そのODの**日間往路も編集後の合計へ明示的に変更**し、出典を手動設定値とします。これは元の日間人数の分割操作とは区別します。OD別manualSplitsを保持するので、別ODの時間分布を一緒に書き換えません。日間ODの手動設定ではそのODの個別時間配分を解除し、目的別の標準分布を使います。

## 帰路

往路の発着を反転し、目的別の帰路率と滞在時間分布を用います。

`帰路の出発時刻 = 往路の時間枠開始 + 固定の往路移動時間 + 滞在時間`

複数の滞在時間と相対重みを受け付けます。UIでは初期の2区分を編集できます。帰路を時間枠へ集約するため、個々の旅客の実時刻を再現するものではありません。帰路が次の運行日以降になる場合も24時間で折り返さず、28時・36時等の時刻で保持します。翌日の列車を自動生成はしません。

固定移動時間のない手動ODについては、帰路の発時刻を捏造せず、生成できない帰路の人数を警告します。元の日間往路とその時間配分は保持します。推計帰路は、往路が実測・手動でも出典をestimatedとします。

## 経路検索との接続

`compareODService` は保存済み需要を読み、検索結果のプロフィールと比較します。需要の再生成や列車への配分はしません。

- 日間ODと検索時刻を含む1時間のOD人数。
- 推計・実測・手動の内訳。
- 各時間枠内で一様到着と仮定した、便が利用可能な人数・利用不可能な時間に到着する人数。
- 利用可能な需要に条件付けた需要加重期待待ち時間。

経路画面ではこれに直通有効本数、乗換込みの有効出発機会、間隔、最速到着を併記します。「便が利用できない時間に到着する人数」は容量超過や積み残しではありません。列車選択・区間配分・混雑率は未計算です。

## 保存と検証

プロジェクトJSONに条件・固定費用・日間往路・生成帰路・時間帯需要・出典・手動配分を保存します。全データセットJSONには徒歩連絡も含めます。時間帯CSVはデータセットID、発着ID、目的、往復区分、開始・終了秒、人数、出典、シナリオIDを持つ明細出力です。時間帯CSVの再読込は未実装で、復元にはJSONを使用します。

読み込み時に目的・係数・駅ID・時間枠・人数・出典、日間入力と保存往路、日間と時間帯の総量を検査します。旧スキーマの単一時間帯需要を自動的に日間需要へ変換しません。
